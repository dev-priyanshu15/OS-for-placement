Unit testing kya hota hai?
Analogy

Socho tumhare ghar ki kitchen hai. Unit test matlab — sirf ek chef ka kaam check karo (kya usne correctly onion kata?), baaki sab — stove, fridge, dusre chef — nakli (mock) karo. Ek function, ek responsibility, ek test.

NestJS mein TestingModule use karte ho ek isolated testing environment banane ke liye. Saari dependencies (Repository, ConfigService) ko mock karte ho with jest.fn().
TestingModule setup
// announcement.service.spec.ts import { Test, TestingModule } from '@nestjs/testing'; import { AnnouncementService } from './announcement.service'; import { getRepositoryToken } from '@nestjs/typeorm'; import { Announcement } from './announcement.entity'; describe('AnnouncementService', () => { let service: AnnouncementService; let mockRepo: any; beforeEach(async () => { // Mock sab karo — database touch nahi hoga mockRepo = { find: jest.fn(), findOne: jest.fn(), save: jest.fn(), delete: jest.fn(), create: jest.fn(), }; const module: TestingModule = await Test.createTestingModule({ providers: [ AnnouncementService, { // Real repo ki jagah mock provide karo provide: getRepositoryToken(Announcement), useValue: mockRepo, }, ], }).compile(); service = module.get<AnnouncementService>(AnnouncementService); }); });

MongoDB Audit Schema + TTL Index
// audit-log.schema.ts (Mongoose) import { Prop, Schema, SchemaFactory } from '@nestjs/mongoose'; @Schema({ timestamps: true }) export class AuditLog { @Prop({ required: true }) userId: string; @Prop({ required: true }) action: string; // 'CREATE' | 'UPDATE' | 'DELETE' @Prop({ required: true }) entity: string; // 'Announcement', 'User', etc. @Prop() entityId: string; @Prop({ type: Object }) metadata: Record<string, any>; @Prop({ default: Date.now }) timestamp: Date; } export const AuditLogSchema = SchemaFactory.createForClass(AuditLog); // TTL Index — 90 din baad auto-delete (compliance!) AuditLogSchema.index( { createdAt: 1 }, { expireAfterSeconds: 90 * 24 * 60 * 60 } );
TTL Index = MongoDB ka auto-cleanup feature. 90 din baad purane logs automatically delete. Storage cost control hoti hai + compliance rules follow hoti hain.
AuditInterceptor implementation
// audit.interceptor.ts @Injectable() export class AuditInterceptor implements NestInterceptor { constructor( @InjectQueue('audit') private auditQueue: Queue, ) {} intercept(ctx: ExecutionContext, next: CallHandler): Observable<any> { const req = ctx.switchToHttp().getRequest(); const methodMap = { POST: 'CREATE', PUT: 'UPDATE', PATCH: 'UPDATE', DELETE: 'DELETE' }; return next.handle().pipe( tap(async (responseData) => { const action = methodMap[req.method]; if (!action) return; // GET skip karo await this.auditQueue.add('log', { userId: req.user?.id, action, entity: 'Announcement', entityId: responseData?.id, metadata: { body: req.body }, timestamp: new Date(), }); }), ); } } // Controller pe use karo @UseInterceptors(AuditInterceptor) @Controller('announcements') export class AnnouncementController { /* ... */ }
Bull Queue Consumer
// audit.processor.ts @Processor('audit') export class AuditProcessor { constructor( @InjectModel(AuditLog.name) private auditModel: Model<AuditLog>, ) {} @Process('log') async handleAudit(job: Job) { await this.auditModel.create(job.data); // MongoDB mein save ho gaya! 🎉 } }
Why RabbitMQ? API response block nahi hoga. Audit log async save hoga background mein. Performance hit nahi aayega user ko.

// file.service.ts import * as Minio from 'minio'; @Injectable() export class FileService { private client: Minio.Client; private bucket = 'announcements'; constructor(private config: ConfigService) { this.client = new Minio.Client({ endPoint: config.get('MINIO_ENDPOINT'), port: +config.get('MINIO_PORT'), useSSL: false, accessKey: config.get('MINIO_ACCESS_KEY'), secretKey: config.get('MINIO_SECRET_KEY'), }); } async uploadFile(file: Express.Multer.File): Promise<string> { // Unique filename — collision prevent karo const filename = `${Date.now()}-${file.originalname}`; await this.client.putObject( this.bucket, filename, file.buffer, file.size, { 'Content-Type': file.mimetype } ); // URL return karo (Postgres mein store hoga) return `http://${endpoint}/${this.bucket}/${filename}`; } async getPresignedUrl(filename: string): Promise<string> { // 1 ghante ke liye valid temporary URL return this.client.presignedGetObject( this.bucket, filename, 3600 ); } }

Top interview questions — Day 6
Q1: Unit test aur integration test mein kya fark hai?
Unit test ek function/service ko isolate karke test karta hai — saari dependencies mock hoti hain. Integration test complete request-response cycle test karta hai — real (or in-memory) DB use hoti hai. Unit tests fast hote hain (ms), integration tests slow (seconds).
Q2: TTL index kya hota hai MongoDB mein?
TTL (Time To Live) index MongoDB ka ek special index hai jo documents ko automatically delete karta hai after a specified time. Audit logs ke liye use karte hain — e.g., 90 din baad automatically cleanup. expireAfterSeconds field set karte hain date field pe.
Q3: Why store file URL in Postgres, not the file itself?
Files ko object storage (MinIO/S3) mein rakhna better hai kyunki: (1) Postgres blobs ke liye optimized nahi hai — slow queries, (2) Object storage horizontally scale hota hai, (3) CDN se serve kar sakte ho, (4) Presigned URLs se secure access milta hai. Postgres mein sirf reference (URL) store karo.
Q4: Presigned URL kya hota hai aur kab use karte hain?
Presigned URL ek time-limited URL hai jo private object ko temporarily access karne deta hai without exposing credentials. Use case: user PDF download karna chahta hai — server 1-hour presigned URL generate karta hai. Client directly MinIO se download karta hai — server load nahi padta. Security bhi maintain hoti hai.
Q5: Audit log async kyun publish karte hain?
Agar audit save synchronously karo, toh MongoDB ka latency user ke API response ko slow karega. RabbitMQ/Bull Queue se audit asynchronously save hoti hai — user ko fast response milta hai, aur background mein log reliably save hota hai. Queue mein retry mechanism bhi built-in hota hai agar MongoDB temporarily down ho.
Q6: 80% coverage target ka matlab kya hai?
80% branch/statement coverage means 80% code paths tests se cover hain. 100% chase karna impractical hai — trivial getters/setters test karna waste of time. 80% sweet spot hai — critical logic tested, edge cases covered, but diminishing returns se bache ho.
Q7: NestJS interceptor vs middleware vs guard — kab kya use karein?
Guard: can this user access this route? (Auth/RBAC) — true/false return. Middleware: request transform karo before route reaches (logging, body parse). Interceptor: request aur response dono pe kaam karo — audit logs, response transform, timing. Interceptor ke paas response data access hota hai — isliye audit ke liye perfect hai.
Power phrases for interviews
→ "We use TTL indexes in MongoDB to enforce data retention policies automatically"
→ "Audit events are published asynchronously via message queue to avoid impacting API latency"
→ "Files are stored in object storage; only the URL reference lives in the relational database"
→ "Presigned URLs provide time-bounded access without proxying through the application server"
→ "We target 80% coverage — focusing on business logic and error paths, not trivial code"
